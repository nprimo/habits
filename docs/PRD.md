# PRD: Habit Tracker

## Problem Statement

Building consistent habits requires tracking. Existing habit trackers are either too complex (gamified streaks, social features) or require a server/account. The user wants a dead-simple, private, offline-first habit tracker that lives on their phone home screen — no accounts, no servers, no noise.

## Solution

A fully client-side PWA: SvelteKit static SPA with SQLite (sql.js WASM) persisted to IndexedDB, deployed to GitHub Pages. A daily checklist view where habits show their goal and progress ("1/1" for daily, "2/2" for weekly). Tap to log. That's it.

## User Stories

1. As a user, I want to create a new habit with a name and goal, so that I can start tracking a behavior.
2. As a user, I want to see all my active habits in a single daily view, so that I know what I need to do today.
3. As a user, I want to tap a habit to log one entry, so that I record that I performed it.
4. As a user, I want to see my progress toward each habit's goal (e.g., "1/1", "2/2"), so that I know if I'm on track for the period.
5. As a user, I want completed habits to visually stand out, so that I feel a sense of accomplishment.
6. As a user, I want to edit a habit's name or goal, so that I can adjust my tracking without losing history.
7. As a user, I want to archive a habit, so that it hides from my daily view but preserves past log entries.
8. As a user, I want to delete a habit permanently, so that I can remove mistakes or abandoned habits.
9. As a user, I want to log entries for past dates, so that I can catch up if I forgot to log.
10. As a user, I want daily habits to reset at midnight, so that each day starts fresh.
11. As a user, I want weekly habits to reset on Monday, so that the week aligns with my calendar.
12. As a user, I want the app to work offline, so that I can log habits without internet.
13. As a user, I want to install the app on my iPhone home screen as a PWA, so that I can open it quickly like a native app.
14. As a user, I want all my data stored locally on my device, so that no one else can access my habit data.

## Implementation Decisions

- **Framework**: SvelteKit with `@sveltejs/adapter-static`. Compiled to static HTML/JS/WASM. No server runtime.
- **Database**: sql.js (SQLite compiled to WebAssembly). Full SQL queries in the browser.
- **Persistence**: sql.js database exported as `Uint8Array` and stored in IndexedDB after every write. Loaded from IndexedDB on app start.
- **Deployment**: GitHub Pages. Static output pushed to `gh-pages` branch.
- **PWA**: Service worker generated by `vite-plugin-pwa`. Caches static assets. Works offline on iPhone Safari.
- **Schema**: Three tables — `habits` (id, name, goal_count, goal_period, status, created_at), `log_entries` (id, habit_id, logged_at, created_at).
- **Goal periods**: `daily` and `weekly` only. Calendar-aligned (midnight reset, Monday reset).
- **One Goal per Habit**: a Habit has exactly one goal (target count + period).
- **Progress**: computed as `SELECT COUNT(*) FROM log_entries WHERE habit_id = ? AND logged_at BETWEEN period_start AND period_end`. Compared to goal target count.
- **No streaks**: not stored or computed.
- **Habit lifecycle**: `active`, `archived`, `deleted`. Archived hides from daily view. Delete cascades to log entries.
- **Routing**: Single page (`/`) for daily view. Optional `/habits` for manage list. Optional `/habit/:id` for detail/edit.

## Testing Decisions

- **What makes a good test**: Test external behavior (CRUD results, progress calculations) not internals (sql.js query strings, IndexedDB save logic).
- **Seams**:
  - **Data layer unit tests** — the sql.js wrapper module (`src/lib/db.ts`). Test: create habit, log entry, compute progress for daily/weekly, edit, archive, delete.
  - **Component tests** — Svelte components via `@sveltejs/vitest-svelte`. Test: daily view renders habits, progress display, tap-to-log updates counter.
- **Test runner**: Vitest.
- **Prior art**: No existing tests in repo — first set of tests establishes conventions.

## Out of Scope

- Multi-user / sync across devices
- Streaks and gamification
- Push notifications and reminders
- Custom periods (monthly, every-N-days)
- Data export / import / backup
- Charts, analytics, or history graphs
- Categories / tags for habits
- Social features or sharing
- Dark mode / theming (v1 only light)
- i18n / localization

## Further Notes

- sql.js loads a 1.3MB WASM file. Acceptable for a PWA; cached by service worker after first load.
- Initially empty state: show "Create your first habit" onboarding with a single CTA.
- No authentication. All data tied to browser IndexedDB — clearing browser data loses everything. User should be informed on first launch.
